# 코딩 컨벤션

이 문서는 일반적인 TypeScript 스타일 가이드가 아니라 **현재 구현·설정·호출 계약에 근거한 이 레포의 작업 지침**이다. 관찰된 버그를 권장 패턴으로 승격하지 않는다. 런타임 코드가 바뀌면 관련 근거와 예시도 함께 갱신한다.

## 작성 절차: 기능 조사 → 독립 구현 → 비교

### 1. 해당 기능·모듈 파악

실제 진입점, 공개 입력·출력, 호출자, 영속 필드, 설정, 오류 처리, side effect를 읽는다. 파일명이나 오래된 AGENTS만으로 동작을 추정하지 않는다. 관찰에 쓰인 파일과 symbol을 각 문서에 남긴다.

### 2. 별도 LLM에 블랙박스 구현 요청

- stateless `completion(prompt, system=...)`을 별도로 실행했다. 도구·레포 파일·대화 이력은 제공하지 않았다.
- 요청에는 기능 요구, 기술 스택, 공개 입출력만 전달했다. 현재 소스, helper 이름, 파일 경로, AGENTS, 원하는 오답은 제공하지 않았다.
- 기능 요구를 현재 코드에서 추출했으므로 “아무 정보도 주지 않았다”는 뜻은 아니다. 구현 내부 관례를 숨겨 독립 구현을 받았다는 뜻이다.
- 생성 코드는 **레포에 적용하거나 실행하지 않았다**. 아래 문서에 기록한 잘못된 예시는 런타임 파일이 아니라 비교용 텍스트다.
- 각 상세 문서에 실제 요청과 실제 응답 발췌를 수록했다. 원문 응답에 실제로 없는 실수를 만들어 LLM 탓으로 돌리지 않는다.

### 3. 현재 코드와 비교해 컨벤션 확정

- **설정 규칙**: compiler·lint·formatter가 선언한 값.
- **현재 계약**: 호출자나 저장소가 기대하는 이름·형식·전이·순서. 새 기능이 기존 경로에 참여할 때 유지해야 한다.
- **관찰된 패턴**: 여러 구현에서 재사용하는 방법. 혼재한 스타일을 강제 단일 규칙으로 꾸미지 않는다.
- **현재 제약·위험**: 연결 대기 누락, 비동기 오류 전파, 미지원 기능 등. 따라 할 컨벤션이 아니다.
- **독립 구현과의 불일치**: 그 구현이 일반적으로 틀렸다는 뜻이 아니다. 기존 계약을 바꾸지 않고 붙이면 잘못되는 경우만 이 레포의 잘못된 예시로 분류한다.
- **합리적인 대안**: 현재와 달라도 올바른 설계라면 대안·개선 방향이라고 표기한다. 이 문서 작업에서 조용히 도입하지 않는다.

## 앞으로 컨벤션을 추가할 때

1. 새 기능에 가장 가까운 현재 코드와 관련 AGENTS를 읽는다.
2. 소스·내부 관례를 포함하지 않은 기능 요구로 새 독립 LLM 요청을 보낸다.
3. 요청과 응답을 보존하고, 문서에는 재현 가능한 요구사항과 관련 응답 발췌를 남긴다.
4. 실제 동작·호출 계약과 대조한다. 맞는 부분은 인정하고 불일치만 구체적으로 설명한다.
5. 기존 문서에 해당 기능의 규칙·근거·올바른 예시·필요한 잘못된 예시를 추가한다.
6. 관련 AGENTS의 경로·요약·링크도 함께 수정한다. 문서만 수정했다면 코드가 바뀌지 않았는지 확인한다.

## 검증 범위와 안전 수칙

문서의 코드 예시는 일부가 발췌이거나 호출자 변수를 사용하는 부분 예시다. 실행 가능한 전체 프로그램으로 보장하지 않는다. 독립 생성안을 실행 검증한 것으로 서술하지 않는다.

- 타입 검사는 외부 서비스 없이 `yarn exec tsc --noEmit --incremental false`로 할 수 있다.
- CLI 도움말도 import 단계에서 로거와 SQLite를 초기화한다. 실제 DB·로그를 피하려면 임시 복사본·작업 디렉터리와 가짜 API 설정을 사용한다.
- 봇·아카이브 실행과 명령 등록 금지는 [루트 AGENTS](../../AGENTS.md)의 지침을 따른다.
- 환경 비밀값, 실제 사용자 대화, 운영 DB 내용은 컨벤션 문서에 넣지 않는다.
