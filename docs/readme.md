# 개발 관련


## 환경설정 파일

`NODE_ENV=prod`이면 `./.env`, 그 밖에는 `./.env.dev`를 사용합니다. 실제 키 목록은 [`.env.example`](../.env.example), 해석 규칙은 [`src/config.ts`](../src/config.ts)를 참고하세요. `SQLITE3_FILE` 설정은 현재 사용하지 않으며, 실패 URL 저장소는 작업 디렉터리의 `./database/failure_urls.db`입니다.

## 실행 순서

### 검색 웹 POC (1.1.0)

봇과 같은 저장소의 `web/`에 정적 화면을 두고 `src/web.ts`를 별도 HTTP 프로세스로 실행합니다. HTML에는 사용자/메시지를 포함하지 않으며, 브라우저가 같은 origin의 API에서 데이터를 가져옵니다. 운영 도메인은 `https://iconttv-discord.probius.dev`입니다.

- `/itvsc`: 웹이 정상일 때 본인에게만 보이는 웹 링크를 발급합니다. 웹이 내려가 있으면 봇 프로세스에서 검색하여 기존처럼 짧은 본문·원문 링크·시각 목록으로 응답합니다. 이 응답도 본인에게만 보이며 사용자별 채널 권한을 적용합니다. `keyword`는 선택(최대 180자), `channel`은 기본 **true**, `embedding`은 기본 false입니다. `channel:false`는 허용된 모든 채널로 시작합니다. 기존 `keep` 옵션은 제거했습니다.
- `/itvweb`: 검색어 없이 웹을 열어 최근 메시지와 서버 설정에 접근합니다. 웹이 내려가 있으면 `현재 웹페이지를 사용할 수 없습니다.`로 응답합니다. 기존 `/itvsetting` 모달도 유지합니다.
- 입장 URL: `/search?token=...&keyword=...&channelId=...&embedding=true/false`. keyword와 channelId는 선택입니다. 웹의 키워드 길이는 최대 200자입니다.
- `keyword`가 없거나 공백이면 최신 메시지부터 보여줍니다. 날짜 필터는 UTC 날짜 경계이며, 표시 시각은 브라우저의 로컬 시간입니다. 페이지당 25개, 최대 100페이지로 제한하고 채널/기간으로 범위를 좁힐 수 있습니다.
- 메시지는 프로필/닉네임/시간/본문과 오른쪽 채널·스레드 링크로 표시하며, 브라우저의 라이트/다크 설정을 자동으로 따릅니다. 채널 그룹은 접기·펼치기를 지원합니다.
- 수정된 메시지는 작성 시각 바로 뒤에 `(수정됨)`을 표시하고, 올리면 수정 시각을 보여줍니다. 첨부 이미지는 최대 240×160 미리보기로 표시하며 서명 URL 만료 또는 로드 실패 시 디스코드 원문으로 이동하는 placeholder로 대체합니다. 스포일러 이미지는 눌러야 로드합니다.
- 사용자·역할·채널 멘션, 정적/움직이는 커스텀 이모티콘, 기본 Markdown(강조·밑줄·취소선·링크·인용·목록·제목·코드 블록·스포일러)을 렌더링합니다. 멘션 이름은 저장된 메타데이터와 현재 결과의 작성자 정보에서 확인하며, 확인되지 않는 이름은 ID로 표시합니다. HTML은 실행하지 않으며 코드 안에서는 Discord 문법도 그대로 표시합니다. Discord 문법 전체를 구현한 것은 아닙니다.
- 디스코드 원문/채널/사용자 링크는 앱을 먼저 호출합니다. Android는 앱 지정 Intent와 웹 fallback을, 데스크톱/iOS는 `discord://`를 사용합니다. 1.8초 동안 화면/포커스 전환이 없으면 웹으로 이동하며, 앱 또는 브라우저 확인창으로 전환되면 자동 이동을 취소합니다. 앱 실행을 확실히 감지할 수 없으므로 수동 `브라우저로 열기` 링크도 제공합니다. 보조키 클릭은 일반 웹 링크 동작을 유지합니다.
- 401과 세션 만료는 상세 메시지를 포함한 닫을 수 없는 다이얼로그로 표시하며 `페이지 나가기` 버튼으로 탭 닫기를 시도합니다. 브라우저가 닫기를 제한하면 탭을 직접 닫도록 안내하고 다른 페이지로 이동하지 않습니다.

#### 세션과 권한

봇/웹은 **동일한 MongoDB, WEB_PUBLIC_URL, WEB_SESSION_SECRET**를 사용해야 합니다. `WEB_SESSION_SECRET`는 랜덤 32바이트 이상이고 기본 유효기간은 `WEB_SESSION_TTL_SECONDS=1800`(30분, 설정 범위 60~86400초)입니다. `WEB_PUBLIC_URL`은 경로 없는 HTTPS origin이어야 하며 dev에서는 LAN 주소를 포함한 HTTP도 허용합니다. 직접 포트에 접속한다면 `http://192.168.0.201:3011`처럼 실제 브라우저 접속 포트도 포함하세요. 프록시를 쓰는 경우에는 브라우저에서 보는 외부 origin으로 설정합니다.

세션은 MongoDB `websessions`에 저장합니다. 링크는 세션 ID·만료 시각·audience를 HMAC-SHA256으로 서명합니다. 링크 소지자는 만료 전까지 발급 사용자로 취급하며 별도 OAuth 로그인이나 일회성 소비는 없습니다. 링크를 공유하면 같은 사용자와 권한으로 접근합니다. 웹에서는 토큰을 HttpOnly/SameSite=Lax 쿠키로 교환하고 주소에서 제거합니다. HTTPS에서는 Secure 쿠키를 사용하며, 쿠키를 교환해도 최초 만료가 연장되지 않습니다. 로그아웃은 해당 브라우저의 쿠키만 제거합니다.

세션 기록은 **만료 후 30일**이 지난 뒤 MongoDB TTL로 정리합니다. 웹 시작 및 링크 발급 시 TTL 인덱스를 준비하며 기존 즉시 삭제 인덱스는 `collMod`로 보관 기간을 갱신합니다. 같은 시점에 `expiresAt < 현재 시각 - 30일`인 기록을 삭제하는 쿼리도 실행하되 기다리지 않습니다. 정리/인덱스 작업 실패는 로그에 남기며 링크 발급을 막지 않습니다. TTL 갱신에는 MongoDB 인덱스 변경 권한이 필요합니다. 기록 보관 기간과 인증 유효기간은 별개이므로 만료된 토큰은 30일 동안 계속 사용할 수 없습니다.

발급 시 Discord의 역할·사용자별 channel overwrites를 반영하여 **ViewChannel + ReadMessageHistory**를 확인합니다. 일반 채널과 활성 스레드뿐 아니라 MongoDB에 기록된 channelId를 Discord에 조회하여 보관된 스레드도 판정합니다. 비공개 스레드는 가입 여부 또는 ManageThreads 권한까지 확인합니다. 삭제됐거나 조회/권한 확인에 실패한 채널은 제외합니다. 여러 스레드의 권한 조회는 최대 5개씩 진행하므로 기록된 스레드가 많으면 발급에 시간이 걸릴 수 있습니다.

허용 채널 목록과 Discord `permissions` 비트필드(문자열)는 **발급 시점의 스냅샷**으로 만료까지 유지됩니다. 세션 만료 전 Discord 역할 변경은 즉시 반영되지 않습니다. `channel` 옵션은 초기 검색 필터이며 웹에서는 허용된 채널 사이를 이동할 수 있습니다. API는 브라우저의 guildId나 사용자 ID를 권한 근거로 사용하지 않고, 일반/의미/최근 조회와 장애 대체 조회 모두 세션의 서버 및 허용 channelId 목록으로 제한합니다.

서버 설정은 기존 명령과 같은 ModerateMembers 기준이며 Administrator도 허용합니다. BE가 permissions로 capabilities를 계산하고 설정 조회/저장에 적용합니다. 저장 가능한 항목은 작은 이미지 변환과 모든 사용자 질문 허용 두 개이고 updatedBy/updatedAt도 갱신합니다. UI에서 버튼을 숨기는 것과 별도로 API에서 검사합니다. 변경 요청은 같은 origin의 JSON 요청만 받습니다.

#### 검색과 장애 대체

봇은 링크 발급 전에 **`WEB_PUBLIC_URL/health`**를 확인합니다. 정상·장애 결과 모두 프로세스 내에서 5초 캐시하며, 동시 요청은 하나의 확인을 공유합니다. 요청 제한은 1.5초이고, 타임아웃·연결 오류·다른 서비스 응답은 장애로 처리합니다. `GET /health`는 인증 없이 웹 프로세스의 준비 상태와 MongoDB 연결 상태를 확인하여 200/503을 반환합니다. 웹 프로세스가 정상이어도 공개 도메인/프록시가 연결되지 않으면 봇은 메시지 응답으로 대체합니다. 웹 장애 중 `/itvsc`는 웹 세션이나 서명 키 없이도 동일한 검색 서비스와 권한 검사를 사용합니다.

최신 목록과 키워드/의미 검색 모두 `iconttv-discord-message_*` Elasticsearch 인덱스를 우선 사용합니다. 키워드 검색은 제한된 simple-query-string 문법(일반 단어는 AND, 구문은 큰따옴표, OR는 `|`)을 사용하며, query-string의 임의 필드 지정은 지원하지 않습니다. 의미 검색은 기존 임베딩 공급자를 재사용합니다.

Elasticsearch 요청 제한은 5초, SDK 재시도는 0회입니다. 검색 의존성 오류가 나면 해당 요청부터 MongoDB로 대체하고, 연속 3회 실패 시 해당 웹 프로세스의 회로를 30초 열어 둡니다. 이후 한 요청만 복구를 확인하고 성공하면 다시 Elasticsearch를 사용합니다. 잘못된 ES 질의(HTTP 400)와 임베딩 공급자 오류는 이 회로의 장애로 세지 않습니다. 검색 결과가 0개라는 이유로 MongoDB를 다시 조회하지 않습니다.

MongoDB 대체는 일반 단어의 대소문자 무시 AND 검색과 날짜 정렬입니다. Elasticsearch의 분석기/관련도와 동등하지 않아 화면에 기본 검색 전환을 표시합니다. 의미 검색은 조용히 다른 방식으로 바꾸지 않고 일반 검색 전환 버튼을 제공합니다. 회로는 프로세스별이며 웹 검색은 서버·사용자 조합당 분당 30회/동시 2회로 제한합니다. 같은 사용자가 새 링크를 발급해도 이 제한은 초기화되지 않습니다. 이 제한은 웹 프로세스별이며 프록시의 전체 트래픽 제한을 대체하지 않습니다.

Elasticsearch 결과는 MongoDB에서 현재 원문·수정 시각·첨부·삭제 상태를 한 번에 확인합니다. 삭제됐거나 원본이 없는 메시지는 표시하지 않으며, Mongo 조회 실패 시 오래된 ES 원문을 노출하지 않고 오류로 처리합니다. 수정으로 비워진 본문이나 제거된 첨부도 검색 인덱스의 옛 내용으로 대체하지 않습니다. 아바타가 raw에 없으면 Discord 기본 아바타를 사용합니다. 검색 총수와 페이지 경계는 인덱스 기준이어서 삭제 반영 지연 시 표시 건수와 차이가 날 수 있습니다. 인덱싱 파이프라인은 이 레포 밖에 있으므로 아직 색인되지 않은 메시지는 정상 ES 조회에 나타나지 않습니다. Mongo 최신 조회용 복합 인덱스는 모델에 선언되어 있으며 실제 DB 생성 여부는 배포 환경에서 확인해야 합니다. TTL 청소 시점과 무관하게 모든 요청에서 만료를 검사합니다.

#### 실행과 배포

```bash
# .env.dev: WEB_PUBLIC_URL=http://localhost:3011 및 개발용 Mongo/검색/서명 키 설정
yarn web-dev

# TypeScript와 정적 웹 자산을 dist/에 빌드
yarn build

# .env 사용, Discord Gateway 로그인 없이 웹 프로세스만 실행
yarn web-start

# 격리된 임시 소스/작업 디렉터리에서 실행하는 회귀 검사
yarn test:web
```

`web-build`는 FE 자산만 `dist/public/`으로 복사합니다. FE는 외부 CDN 스크립트나 별도 번들러 없이 ES module/CSS로 동작합니다. Docker 이미지에도 같은 자산을 포함하며 compose의 `iconttv-discord-web`은 호스트 IP를 지정하지 않은 `${WEB_PORT:-3011}:${WEB_PORT:-3011}` 포트 매핑으로 노출합니다. `.env`의 `WEB_PORT`를 호스트·컨테이너 포트와 웹 리스너에 동일하게 적용하며, 미설정 또는 빈 값이면 3011을 사용합니다. 도메인의 HTTPS 리버스 프록시가 `/health`, `/search`, `/settings`, 정적 파일과 `/api/*`를 이 웹 서비스로 전달해야 합니다. 봇 컨테이너에서도 `WEB_PUBLIC_URL`로 접속할 수 있어야 합니다. 토큰이 최초 URL에 있으므로 프록시 access log에는 query string을 기록하지 않도록 설정하세요. 응답은 no-store/no-referrer 정책을 사용합니다.

운영 적용에는 환경변수 설정, 도메인/HTTPS 프록시 연결, 새 이미지 배포, 변경된 슬래시 명령 등록 및 봇 재시작이 필요합니다. 빌드/회귀 검사는 이 작업들을 수행하지 않습니다. 아래 명령 등록/봇 실행 절차는 운영자가 별도로 수행합니다.

1. `/` 명령어 등록

```bash
yarn cmd-dev
```

2. 봇 실행
```bash
yarn dev
```
